# Mac 手柄输入（待真机验收）

游戏窗口与新旧启动器的测试界面共用 `S2AControllerInput`，只在主线程调用。
不安装或清空 GameController 的全局回调，不改动 shell 导航模块。

## 使用与配置

默认发布前端的游戏「键位设置」新增「手柄设备与输入测试」：

- 系统手柄：保留最近有输入的可用扩展手柄自动选择；也可指定型号。
- 北通宙斯 / NS Pro HID：显式启用，仅匹配 `057e:2009`，要求用户选择设备，
  或仅连接一只匹配手柄。**不会自动把所有相同 VID/PID 的原装手柄判为北通。**
- 禁用手柄：仍保留键盘、鼠标输入。
- 输入测试显示归一化的物理按键与四轴，可按手柄键绑定到当前目标；重复绑定仍阻止保存。
- 键盘修饰键按下先等待，普通键按下时录组合键；单独松开修饰键时录该键。
  Esc 取消录入；Esc 绑定使用常用键列表。失焦取消录入。

保存后下次游戏启动生效。**运行游戏的宿主也必须由新代码重新构建**，仅替换启动器不够。
旧启动器保留新设备配置并使用同一测试采样器；新的设备选择/手柄录入界面在默认 NX2Apple 前端。

schema 1 增加可选字段（省略即原来的系统自动选择）：

```json
"controller": {"backend": "nspro-hid", "device": ""}
```

backend 为 `system` / `nspro-hid` / `disabled`；device 是不含 NUL、最多 255 UTF-8 字节的字符串。
这是 Mac 输入设置：共用解析器保留字段，但不改变 iOS 的设备管理行为。

GC 没有稳定硬件 ID，当前按 category/vendor 选择；相同型号多只时显式选择返回中立，
不猜哪只属于玩家，可用自动模式。HID 用本机 IORegistry entry ID，跨进程可识别同一次连接，
重连/重启后可能变化，需重新选择。指定设备断开不会偷偷换成别只。

## 协议及边界

- HID 模式与系统模式互斥，不叠加重复输入；非独占打开设备。
- 请求 Switch 子命令 `03 30`，只接收包含 report ID 的完整 `0x30` 报告，至少 49 字节。
- 解出 16 个游戏按键和四个 12-bit 轴；固定中心 2048，归一化后只应用一次用户死区。
- 断开、无匹配、多个候选、报告停止超过 500 ms 均输出中立；时间使用单调时钟。
- 报告停止阈值是输入释放保护，不是重连重试或掩盖失败；打开/报告模式请求失败显示明确状态。
- 映射编辑器失去应用焦点释放 HID，避免后台编辑器与游戏争用输出命令。
- 未实现 USB 专用初始化握手、工厂/用户校准读取、震动、HOME/截图或多玩家分配。
- NS Pro HID 体感链路已在工作区实现，尚未真机验收，见下文；系统驱动模式的体感未接入。
- 无设备连接时不能证明真实北通固件/蓝牙链路兼容；原装 Pro 真机负对照也尚未完成。

## 系统驱动逐连接采样层（仍未启用生产四槽）

新增 `S2ASystemControllerSlots`，仅主线程使用，由调用方注入当前 GCController 数组。
它不自行枚举硬件、不安装任何全局回调、不设置 playerIndex、不打开 HID：

- 以对象身份区分同时连接的同型号系统手柄，分配随机、不持久化的连接 token。
  连续库存中的对象保留 token；断开、stop 后重新出现则获得新 token。
  **token 不是硬件序列号，不能存为长期用户选择，不能据此认定 GC/HID 是两个设备。**
- 使用纯 C 分配器，逐槽 capture 对应控制器；返回用户映射/死区之前的原始命名输入。
  不选择“最近按键”的另一个控制器。没有键鼠混入、HID fallback 或反馈发送。
- 支持准备阶段 auto/system/disabled；nspro-hid 明确拒绝，当前配置与所有权保持不变。
  指定连接优先、重复指定留空且预留、不存在指定不回退、存活自动槽不压缩。
- 失焦清输入但保留连接；空库存、超出64连接上限清空；不偷偷截断库存。
- 抽出 `s2a_system_pad_values` 复用旧命名/按键布局逻辑，旧单槽选择语义保持不变。

## 现有 Mac 系统驱动六轴生产接线

原来的 `S2AControllerInput.readMotion` 只读 NS Pro 原始 HID 状态；system 分支虽有按键，
没有读取 GCMotion。现在现有 Mac 主循环的 system 分支按当前选中 pad 绑定运动来源：

- 仅游戏请求六轴时绑定，要求 `hasRotationRate`；没有传感器明确返回不可用，不猜品牌/模式。
- 只在 `valueChangedHandler` 空闲时安装自身回调，不覆盖他人handler；被换走时放弃读取。
  这是旧“从不安装GC handler”约定的明确变更：**不覆盖已有handler**，允许拥有空闲motion handler。
- 仅在自身把手动传感器从关变开、且仍持有handler时关闭；预先开启的传感器不擅自关闭。
- 回调写独立带锁mailbox，游戏线程仍只读现有host POD；不在回调等待主线程。
  解除时先关闭mailbox，旧回调只持有已关闭mailbox，不持有sampler或新连接。
- 回调接收时刻使用CLOCK_MONOTONIC，轮询不伪造新时间戳；250ms过期清空。
  GCMotion加速度重力方向取反为现有raw支撑反力约定，rad/s换成deg/s；拒绝非有限/float溢出。
  实际设备坐标/模式仍需验收，不能据此宣称北通特定型号/模式已修好。
- 现有失焦/配置变化/进程内重启generation会关闭旧mailbox；NS Pro ACK路径保留。
